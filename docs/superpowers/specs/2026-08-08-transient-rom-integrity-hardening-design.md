# Transient-ROM Integrity Hardening Design

## Purpose

This specification hardens the optional `--thermal-mode transient-rom` path
after a branch-wide audit found provenance, cache, numerical-consistency and
test-oracle gaps.  It preserves the steady Eq. (13) workflow and every
existing R1/R2/run directory.  The result remains an exploratory extension:

```json
{
  "thermal_mode": "transient-rom",
  "non_formal": true,
  "paper_equivalent": false
}
```

The goal is not to claim that a filesystem attacker cannot replace an entire
accepted experiment, which would require an external signing/immutable-store
service outside this project.  The goal is stricter scientific reproducibility:
every result consumed by the code must be reproducible from the current
declared inputs, stored calibration artifacts, and canonical numerical helpers.
In particular, self-consistent JSON fields and their own hashes are never
sufficient evidence when their value can be recomputed locally.

## Invariants

- `--thermal-mode steady` keeps its current code path, Eq. (13) artifacts,
  arguments and tests unchanged.
- Transient-ROM owns only `shared_l2`; all non-L2 modules must equal the
  current `modules.json` baseline in name, kind, dimensions, tier and position.
- Calibration always has exactly eight training HotSpot cases and two
  independent holdout HotSpot cases.  Optimizer execution performs zero
  HotSpot/subprocess calls.
- Dynamic power scales by `s=f/f0`; leakage is unchanged; each window duration
  scales by `1/s`.  The generated trace records and validates this transform.
- Every accepted ROM-owned JSON artifact has all three classification fields
  above.  Acceptance rejects a contradictory classification.
- Reuse is possible only for a complete, non-symlinked, package-contained
  artifact tree whose package manifest, saved source copies and current inputs
  agree.
- A frequency grid is finite, strictly positive, contained in `[fmin_ghz,
  f0_ghz]`, and contains both endpoints exactly once after canonical sorting.
- ROM and HotSpot use the same fixed `pss_period_repeats` horizon.  ROM records
  the final-period peak and final adjacent-period full-grid delta after all
  repeats, rather than stopping at the first transiently small delta.
- `bips2_trans` is numeric only after trace-bound final real-HotSpot PSS
  validation and a successful R2.  Invalid evidence writes an auditable
  `rom_final_validation_failed` result and suppresses R2.

## Evidence Boundaries

### Calibration package

The package owns copies of `modules.json`, source power windows, config,
design, all case layouts/power traces/temperature traces, model, fit report,
holdout report, acceptance and an artifact inventory.  All paths are relative,
regular files under the package; every path component is checked with `lstat`
before resolution, so a symlink cannot escape the package.

The current run independently derives the baseline layout from current
`modules.json`; its non-L2 modules must equal `design.base_layout`, while each
saved case must equal the canonical layout for its anchor/holdout point.  The
interpolation domain must name exactly the saved training coordinates: bilinear
corners map to their anchors, and a Delaunay point list maps one-to-one to its
anchors.

For each case, the saved trace manifest carries a canonical input identity:
SHA-256 of modules, layout, power windows and config, power-trace identity,
frequency scale, period count, windows per period, grid unit names/count, and
the expected dynamic/leakage/time transform.  Reuse recomputes PRBS power
windows and emitted power-trace rows from the saved source windows and
multipliers.  It parses the temperature trace with the canonical PSS helpers.
Malformed/truncated/grid-inconsistent training evidence is rejected before
model fitting or optimization.  Holdouts are additionally recomputed from the
saved model through the shared, non-publishing holdout gate; the resulting
validation report must equal the saved report.

### Cached optimizer output

`optimization_report.json` is a cache, not scientific authority.  Reuse must
derive the requested identity from current modules/config/power/HotSpot and
the saved design; then deterministically replay the ROM-only lattice and local
refinement search into a fresh in-memory report.  The cached selected layout,
candidate coordinates, frequency grid, wire calculation, ROM temperatures and
predicted BIPS must exactly match the replay.  Cache replay is permitted to
consume CPU/NumPy time but makes zero HotSpot calls.  An output directory must
be a new regular descendant of its requested root, must not be nested under an
accepted package or any read-only input, and must contain no symlink component.

### Final HotSpot validation

Each frequency case generated by `search_layout_frequency()` writes a trace
manifest with an input identity for current modules, proposed layout, power
windows, config and HotSpot executable, plus the canonical scaled-power trace
hashes and grid identity.  Final replay checks that identity against the
selected layout and current invocation before it compares PSS, peak, safety,
frequency brackets and state.  It recomputes the full-grid PSS and final-period
peak from the recorded `transient.ttrace`; it also recomputes the canonical
frequency search from those evaluations.  Missing, stale, malformed or
mismatched evidence is `validation_contract_error`, writes
`final_validation_failure.json`, and never calls R2.  A genuine converged but
fully unsafe grid remains `thermally_infeasible`; any PSS nonconvergence remains
`pss_nonconvergence`.

## Numerical Contract

The ROM state propagation evaluates all `pss_period_repeats` complete periods.
It still records every adjacent end-of-period full-grid delta, but convergence
is determined only from the last one, matching the HotSpot trace evidence.
The final-period peak includes its initial state in both implementations.

The existing POD/ridge/logm gates stay unchanged.  Tests add an independent
analytic stable state-space oracle: known continuous/discrete matrices and
power vectors generate trace samples without calling production ROM evaluation
or fitting helpers.  Eight independently generated training trajectories plus
two independently generated holdouts must recover a stable model sufficient to
pass the gates and drive the ROM-only optimizer.  Separate mutations of model,
power, trace, layout, identity and cached prediction must fail.

## Error Semantics

Input/output topology and identity violations found before external work raise
`ValueError` with no output mutation.  Package/trace evidence failures after a
transient final result exists produce a classified, atomic failure summary.
Tool execution failures remain `tool_error`; malformed evidence is never
reported as thermal infeasibility.  No hardening task invokes gem5, McPAT,
CACTI, HotSpot, R1 or R2 in tests.

## Test Strategy

Tests use deterministic two-cell, multi-window/multi-period fixtures whose
traces are specified before the expected PSS/frequency reports are derived.
They assert emitted dynamic values equal source values times `s`, leakage equals
the source, and total equals their sum.  Every positive fixture has an
independent oracle; every key artifact has one mutation test that proves the
gate is active.  The relevant suite is:
