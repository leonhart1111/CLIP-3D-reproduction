# CLIP-3D 改进效果不足的调查、验证与修正

日期：2026-07-29

## 1. 结论

当前两个正式 32×32 单点实验不能支持“已经复现论文中的显著提升”这一结论。严格按论文算法 1 运行时，MATMUL 的 BIPS2 改进为 0%，FFT 为 -0.778%。这不是一个仍可用单个 `alpha`、`beta` 或热阻系数修好的局部问题，而是以下三类限制叠加的结果：

1. 论文没有公开 McPAT XML、完整模块 floorplan 和 Cool-3D layer configuration。表 III 的功耗与泄漏比例可以近似对齐，但三个固定布局锚点不能由同一热堆叠同时对齐。
2. P1 中唯一可移动的 L2 只占总功耗的 1.31%（MATMUL）和 2.40%（FFT）。固定的核心块承担了约 98% 的功耗，因此只移动 L2 对真实 HotSpot 温度的影响天然很小。
3. 优化器看到的连续代理信号没有稳定迁移到正式 32×32 HotSpot；连续平均线延迟虽然变小，但四舍五入后送入 gem5 R2 的平均周期没有变化。

已经修正了能够确认的软件问题，并为每次新优化增加了可观测性诊断。未通过验收的参数保留为“候选/诊断值”，不再标记为已恢复论文参数。

## 2. 论文流程与当前实现是否一致

论文算法 1 的严格路径是：

1. gem5 R1 产生 IPC1 和活动统计；
2. McPAT 产生模块动态功耗、泄漏功耗和面积；
3. CACTI 产生缓存几何与访问周期；
4. 公式 (14) 在优化器内部提供可微热代理；
5. 公式 (13) 把代理温度转换为可持续频率；
6. 公式 (15) 用 `-IPC × f_sus + lambda_wire × IPC × mean_wire_delay` 搜索 L2 位置；
7. 搜索结束只对最终布局运行一次正式 HotSpot；
8. 把离散缓存、TSV 和线延迟反标给 gem5 R2，得到 IPC2；
9. 最终报告 `BIPS2 = IPC2 × f_sus`。

`layout_optimizer.validation_policy=paper-single` 已实现这一路径。fixed-bin 和 CLIP-3D 是两个独立点；严格模式不会在选择阶段偷看 fixed-bin 的 HotSpot 结果，也不会运行两次 HotSpot 后择优。

论文文本自身存在两处无法由代码唯一消解的矛盾：

- 方法段写环境温度 45°C，但实验段、公式 (13) 和表 III 的数值只与 25°C 相符。因此正式配置使用实验值 25°C。
- 第三部分-C称公式 (6) 的延迟不依赖 `(x,y)`，第三部分-E又把连续面内线延迟放入公式 (15)，第四部分-D还把布局相关线周期反标给 R2。当前实现同时记录连续平均延迟、整数平均周期和整数最坏周期，避免把三者混为同一实验。

## 3. 已验证的根因

### 3.1 单锚点热阻是过拟合

旧值 `local_resistance_scale=8.72` 只精确匹配 FFT 64 kB/1 MB，不能迁移。当前使用三个表 III 锚点做功耗与热堆叠交叉验证：

| 锚点 | 观测功耗误差 | gamma 误差 | 固定布局温度误差 |
|---|---:|---:|---:|
| MATMUL 128 kB/2 MB | 0 W | 0 | +5.38°C |
| FFT 32 kB/256 kB | +0.2395 W | -0.00109 | +0.68°C |
| FFT 64 kB/1 MB | -0.2331 W | +0.00112 | -3.62°C |

功耗最大相对误差只有 1.57%，gamma 最大误差约 0.00112，但共同热堆叠的最大温度误差仍为 5.38°C。三个锚点反推出的有效局部热阻缩放分别约为 4.06、6.24 和 7.14，不可能由一个共同常数同时满足。

分别拟合硅和 TIM 的有限差分雅可比满秩，但线性化 RMSE 仍为 3.33°C，超过 1°C 验收门限，因此也被拒绝。证据文件：

- `results/calibration/table3_crosscheck_20260729/final_anchor_audit.json`
- `results/calibration/table3_crosscheck_20260729/stack_component_fit.json`

这说明缺失量更可能是模块布局/面积、McPAT XML 活动映射或未公开封装层，而不是一个可以任意调整的总热阻。

### 3.2 原核心功耗图过度聚合，现已细化

旧实现把每个核心除 L1 外的全部逻辑压成一个均匀矩形，削弱了热点的位置敏感性。现在按 McPAT `-print_level 5` 拆为：

- `core_ifu`
- `core_rename`
- `core_lsu`
- `core_mmu`
- `core_exec`
- `core_other`
- 独立的 L1I、L1D

两个例子都生成 34 个物理模块；如果输入是旧的简化 McPAT 文本，解析器才回退到 `core_logic`。该修正提高了功耗图的物理粒度，但没有凭空增加可移动 L2 的功耗。

### 3.3 可移动功耗太小

| 工作负载 | 总功耗 | L2 功耗 | L2 功耗占比 | L2 面积 | L2 功率密度 |
|---|---:|---:|---:|---:|---:|
| FFT 64 kB/1 MB | 16.0069 W | 0.3846 W | 2.4025% | 43.3524 mm² | 0.00887 W/mm² |
| MATMUL 32 kB/512 kB | 15.6441 W | 0.2047 W | 1.3085% | 26.0166 mm² | 0.00787 W/mm² |

L2 不但功耗低，而且面积大、功率密度低。移动它不会改变固定核心约 15.4–15.6 W 的主热点，因此 32×32 HotSpot 的位置温差只有约 0.3°C。

### 3.4 代理的绝对误差不大，但位置排序不可靠

热优化关心的是“往哪个方向移动会更冷”，不是只关心绝对 RMSE。修正外部验证分组后，中心点公式 (14) 代理得到：

| 验证集 | 温度 RMSE | 组内位置 Spearman |
|---|---:|---:|
| 16×16 留出样本 | 0.533°C | 0.600 |
| 正式 32×32 外部样本 | 0.652°C | 0.252 |

`beta` 乘的是底层总功耗，而当前合法 P1 样本全部把 L2 留在顶层，底层功耗在位置扫描中不变化。因此 `beta` 在这个实验中不可辨识。用不同工作负载的绝对温差拟合出一个 beta，不等价于测到了跨层惩罚。

面积积分代理也没有通过：所有样本的空间 Spearman 约为 0.736，拟合的跨层权重落到上界 1.0。两个代理都不能写入正式配置。

### 3.5 连续线延迟改善被整数接口隐藏

| 工作负载 | fixed 平均周期 | CLIP 平均周期 | fixed→CLIP 取整 | 最坏周期 fixed→CLIP |
|---|---:|---:|---:|---:|
| FFT | 1.0320 | 0.7910 | 1→1 | 3→1 |
| MATMUL | 1.2103 | 0.7638 | 1→1 | 3→1 |

论文公式 (15) 使用连续平均延迟，所以优化器能看到改善；当前 paper-mode R2 使用取整后的平均周期，两个布局得到完全相同的 gem5 overrides，因此 IPC2 完全相同。

最坏路径确实从 3 周期降到 1 周期。把共享互连时序按最坏路径反标是合理的保守扩展，但它不是论文明确写出的“平均线延迟”实验，必须单独标注，不能用来替换论文结果。

### 3.6 正式 32×32 端到端结果

| 工作负载/方法 | Tmax(f0) | f_sus | IPC2 | BIPS2 | 相对 fixed |
|---|---:|---:|---:|---:|---:|
| FFT fixed | 120.78°C | 1.026341 GHz | 3.417362 | 3.507379 | 基线 |
| FFT 论文严格 CLIP | 121.07°C | 1.018361 GHz | 3.417362 | 3.480107 | -0.778% |
| FFT 量化线目标扩展 | 120.95°C | 1.021657 GHz | 3.417362 | 3.491372 | -0.456% |
| MATMUL fixed | 119.88°C | 1.076668 GHz | 1.963124 | 2.113633 | 基线 |
| MATMUL 论文严格 CLIP | 119.88°C | 1.076668 GHz | 1.963124 | 2.113633 | 0% |
| MATMUL 量化线目标扩展 | 119.86°C | 1.077216 GHz | 1.963124 | 2.114708 | +0.051% |

这两个例子都没有论文量级的提升。量化目标减少了代理导致的回退，但不构成显著收益。

## 4. 本轮修改

### 4.1 优化器可观测性诊断

`workflow/floorplan/optimize_layout.py` 的新报告字段包括：

- `baseline.proxy_tmax_c` 与 `baseline.layout_delays`
- `predicted_deltas.proxy_tmax_c`
- 连续平均线周期差
- 取整平均和最坏线周期差
- `movable_l2_power_fraction`
- `paper_mean_r2_cycle_changed`
- `conservative_maximum_r2_cycle_changed`
- 对低可移动功耗和量化隐藏的明确警告

本例的机器可读审计位于：

- `results/validation/improvement_audit_20260729/fft_64k_1m_optimizer_audit.json`
- `results/validation/improvement_audit_20260729/matmul_32k_512k_optimizer_audit.json`

### 4.2 多点 lambda_wire 标定

`workflow/r2/calibrate_lambda_wire.py` 保留原双点有限差分命令，同时新增至少三个不同整数延迟级别的 OLS 回归模式。报告包含：

- `IPC2 = intercept - k × wire_cycles`
- `R²`
- 单调性违例
- 每点残差
- 当前工作负载是否通过验收
- 跨工作负载是否已验证

当前 `lambda_wire=0.000962332...` 仍只是一个 FFT 单点有限差分，不能称为共享正确值。

### 4.3 外部代理验证分组修正

`workflow/thermal/calibrate_proxy.py` 的外部样本改用：

```text
GROUP:SAMPLE=CASE_DIR
```

同一工作负载的 fixed、center、optimized 现在属于同一组，可以真正计算位置相关系数。验收从“相关系数存在”提高为 `spatial Spearman >= 0.8`。

### 4.4 正式配置不再声明参数已恢复

`configs/experiments/clip3d_constrained_5p0_multianchor.json` 新增 `parameter_acceptance`。当前四项均为 false：

- 表 III 功耗与热堆叠共同恢复
- 热代理方向
- lambda 跨工作负载迁移
- 正式论文级结论许可

这不会阻止诊断运行，但可以防止把候选参数误写成已验证参数。

## 5. 如何按科学方式继续测参数

### 5.1 McPAT 功耗与 gamma

1. 冻结 R1、McPAT 版本、45 nm 节点和 XML 映射。
2. 只使用表 III 公开的 `P(f0)` 与 `gamma` 拟合动态/泄漏比例，不使用优化增益作为目标。
3. 至少保留一个工作负载和一个缓存配置作完全未参与拟合的验证点。
4. 接受条件：所有验证点功耗误差 <3%、gamma 误差 <0.02。
5. 每工作负载缩放只能用于解释局部缺失 XML，不应外推到没有锚点的 STREAM/STENCIL。

### 5.2 热堆叠

1. 在 fixed-bin 上使用至少三个公开锚点。
2. 分别对硅和 TIM 有效电阻做 ±10% HotSpot 探针，构造有限差分雅可比。
3. 只拟合固定布局绝对温度，不看 CLIP-vs-fixed 收益。
4. 接受条件：雅可比满秩、验证 RMSE <1°C、最大残差 <2°C。
5. 当前不通过时停止增加自由参数；优先获取原作者 LCF、floorplan 和 XML。

### 5.3 alpha、beta 与跨层权重

1. 每个训练架构生成至少 3×3 顶层位置；如果要测 beta，必须额外包含合法的跨层候选，使底层功耗发生变化。
2. 使用 16×16 只能做快速训练；必须在未参与拟合的 32×32 位置上验收。
3. 目标以组内中心化温差和位置排序为主，绝对 RMSE 为辅。
4. 接受条件：验证空间 Spearman >=0.8、跨分辨率仍 >=0.8、参数不在边界、雅可比可辨识。
5. 如果合法 P1 中 L2 只能在顶层，则 beta 应固定为 0 或标记不可辨识，不能伪拟合。

### 5.4 lambda_wire

对同一 R1、同一缓存配置和同一工作负载，构造只改变注入线周期的 0/1/2/3 四个 R2：

```bash
python -m workflow.r2.calibrate_lambda_wire \
  --sample c0=R2_C0/r2_result.json,R2_C0/r2_latency.json \
  --sample c1=R2_C1/r2_result.json,R2_C1/r2_latency.json \
  --sample c2=R2_C2/r2_result.json,R2_C2/r2_latency.json \
  --sample c3=R2_C3/r2_result.json,R2_C3/r2_latency.json \
  --ipc1 IPC1 \
  --frequency-ghz F_SUS \
  --output results/calibration/LABEL_lambda_series.json
```

每个工作负载分别回归。单工作负载接受条件是 R² >=0.95 且 IPC 随延迟单调不增；是否使用统一 lambda，要看四个工作负载的斜率分布，不能只用 FFT。

## 6. 怎样才可能得到显著且可信的改进

不能以“必须得到显著提升”为调参目标。合理路径只有以下三类：

1. **严格复现**：向作者获取 McPAT XML、每模块 floorplan、Cool-3D LCF、原始功耗图和 R2 线周期映射。得到这些输入后重新做盲测。这是恢复论文数字的首选路径。
2. **论文一般方法的扩展**：把论文第三部分-E提到的“可选大核心块”加入可移动集合。当前 98% 固定功耗是热优化没有杠杆的根因；移动高功率核心块可能产生真实热收益，但应明确标为扩展，不是 P1 的仅移动 L2 对照。
3. **最坏路径 R2 扩展**：共享同步互连按最坏 core-to-L2 路径定时，而不是平均路径。本例整数最坏路径从 3 降到 1，值得运行 R2 灵敏度实验；若 IPC 显著上升，应单独报告为 conservative-maximum 模式。

最终只有满足以下条件才可报告“显著改进”：

- 参数只由 fixed/训练数据拟合；
- 代理在未见过的 32×32 位置上通过方向验收；
- fixed 与 CLIP 使用相同物理模型和相同 R1；
- 每种布局独立运行最终 HotSpot 和对应 R2；
- 多个工作负载、多个缓存点的置信区间不跨 0；
- 不通过的点也完整保留并报告。

## 7. 当前建议

在获得原始 XML/LCF 前，不应立即跑完整 80 点 CLIP 布局扫描。先做两个便宜且有判别力的实验：

1. 对 FFT、MATMUL、STENCIL、STREAM 各选一个点，完成 0/1/2/3 周期 R2 灵敏度，判断论文大收益是否可能来自线延迟映射。
2. 选一个 L2 功耗占比最高、一个最低的点，在正式 32×32 下做少量盲位置验证；如果空间排序仍低于 0.8，则停止调 alpha/beta，转向获取原始物理输入或扩大可移动模块集合。

正式 R1 结果无需重跑；上述实验都从已有 R1 目录开始。
